# claude-code-token-metrics — Design

**Date:** 2026-05-15
**Status:** Approved (brainstorming)
**Type:** Personal tooling — ships in its own public GitHub repo, not the IAKUVO codebase.

## Problem

I want insight into my Claude Code token usage broken down by **model** and **over time**,
**grouped by git repository** (so all worktrees of one repo collapse into one group, but
separate repos stay distinct).

I run a mix of Claude Squad managed sessions and raw terminal sessions. Claude Squad has
**no hooks and no lifecycle events**; when an instance is killed (`D`), it closes the tmux
session and runs `git worktree remove -f` plus deletes the branch. Claude Code itself
auto-cleans orphaned worktree session directories after `cleanupPeriodDays`. The transcript
directory under `~/.claude/projects/` is keyed to the worktree path, so once a finished task's
worktree is gone, its transcript is orphaned and eventually garbage-collected.

Every existing analytics tool (ccusage, token-dashboard, claude-usage, tokscale, etc.) reads
live `~/.claude/projects/*.jsonl` at runtime. That assumption is broken for my workflow:
finished-and-killed Squad tasks vanish before analysis. **The unsolved problem is durable
capture before cleanup destroys the data** — not the analytics, which ccusage already does well.

## Non-goals

- No effort/thinking-level dimension. Claude Code transcripts on this machine record zero
  `"type":"thinking"` content blocks (0 of 6485 files) and `usage` carries no thinking-token
  count. Effort is not derivable from historical data, so it is dropped. Model
  (Opus/Sonnet/Haiku) is the effort proxy.
- No live dashboard, no statusline, no charts/HTML. CSV/JSON export only.
- No reimplementation of ccusage's aggregation. We reuse ccusage.
- No cloud sync. Local snapshot store only.

## Architecture

Three components with clean separation:

```
┌─────────────┐   SessionEnd hook    ┌──────────────────┐
│ Claude Code │ ───────────────────▶ │  capture          │
│  sessions   │   + periodic sweep   │  (snapshot store) │
└─────────────┘                      └────────┬─────────┘
                                               │ reads
                                      ┌────────▼─────────┐
                                      │  analyze          │
                                      │  (repo-group +    │
                                      │   ccusage + CSV)  │
                                      └──────────────────┘
```

1. **capture** — gets transcripts into a durable local store before Squad / Claude Code
   delete the worktree.
2. **store** — `~/.claude-token-metrics/snapshots/` — gitignored, never committed.
3. **analyze** — resolves each transcript to a git repo, runs ccusage for aggregation,
   emits CSV + JSON.

The **public repo ships only code, the hook script, and a `setup` command.** Transcript
snapshots contain prompts, source code, and potentially secrets — they stay strictly local
and are never committed to any repo, public or private.

## Component 1 — Capture

Two triggers, belt-and-suspenders:

### SessionEnd hook

- Script: `hooks/snapshot-transcript.sh`, installed into `~/.claude/settings.json` under the
  `SessionEnd` event by the tool's `setup` command (appended to the existing `hooks` object —
  must not clobber the user's current `PreToolUse` / `Stop` / `Notification` hooks).
- Claude Code passes the hook a JSON payload on stdin containing the transcript path.
- The hook copies that file into the snapshot store, preserving the source project-dir name
  so repo resolution still works later.
- Transcripts are append-only, so re-copying on every session end is safe — last write wins.
- Fires for every session, Squad-managed or raw terminal.

### Periodic sweep

- Command: `claude-code-token-metrics sweep`, run via launchd roughly every 4 hours.
- `rsync`s all of `~/.claude/projects/*.jsonl` into the snapshot store.
- Catches anything the hook missed: crashes, killed sessions, hook failures.
- `rsync` makes it cheap and idempotent.

### Snapshot store layout

```
~/.claude-token-metrics/snapshots/<project-dir-name>/<session-uuid>.jsonl
```

Mirrors the source directory structure. Append-only on our side — the tool never deletes
snapshots. This is the durable archive.

## Component 2 — Repo grouping & resolution

Transcripts are keyed by worktree path
(e.g. `-Users-...-claude-squad-worktrees-fix-drift-migrations_18afaafbb...`). Worktree dirs are
deleted by analysis time, so `git rev-parse` against them often fails.

Resolution heuristic, applied per transcript by `claude-code-token-metrics analyze`:

1. Read the `cwd` field from inside the transcript (present on every line).
2. If `cwd` is a live path → `git rev-parse --show-toplevel`, then `--git-common-dir` to fold a
   worktree back to its origin repo.
3. If `cwd` is dead (Squad-deleted worktree) → normalize the path: strip the trailing
   `_<hash>`, strip the `worktrees/<branch>` segment, map back to `repo_path`. Cross-reference
   `~/.claude-squad/state.json` (records `worktree.repo_path` per instance) for an exact
   mapping where the instance still exists.
4. Anything unresolvable → bucketed as `unknown`, surfaced in output. Never silently dropped,
   never a crash.

The repo group key is the canonical origin-repo path.

## Component 3 — Analysis & export

- For aggregation, run **ccusage** against the snapshot store (`--json`, pointed at the store
  via ccusage's custom-data-directory flag). ccusage provides the model + token + time
  breakdown.
- The tool's own job is the layer ccusage lacks: join each session to its resolved repo group,
  then emit two pairs of outputs.

### Outputs

**Session-level** (`sessions.csv` + `sessions.json`) — one row per transcript:

| column | meaning |
|---|---|
| `repo` | canonical origin-repo path (or `unknown`) |
| `session_id` | transcript UUID |
| `model` | model id (e.g. `claude-opus-4-7`) |
| `date` | session date (ISO) |
| `input_tokens` | input tokens |
| `output_tokens` | output tokens |
| `cache_creation_tokens` | cache-creation input tokens |
| `cache_read_tokens` | cache-read input tokens |
| `cost` | cost from ccusage |

**Daily rollup** (`daily.csv` + `daily.json`) — one row per `(date, repo, model)`, with the
token columns summed and a cost total.

### Error handling

- ccusage not installed → clear, actionable install message; exit non-zero.
- Malformed transcript line → skip the line, count it, report the count at end of run.
- Unresolved repo → `unknown` bucket; the run still completes.

## CLI surface

Single binary `claude-code-token-metrics` with subcommands:

- `claude-code-token-metrics setup` — install the SessionEnd hook into
  `~/.claude/settings.json` (idempotent, merge-not-clobber) and install the launchd sweep job.
- `claude-code-token-metrics sweep` — one-shot rsync of `~/.claude/projects` into the snapshot
  store.
- `claude-code-token-metrics analyze [--out <dir>]` — resolve repos, run ccusage, write the
  four output files.

## Testing

- **Repo-resolution heuristic** is the only substantial logic. Unit-tested against fixture
  `cwd` values: live repo, live Squad worktree, dead Squad worktree, raw terminal session,
  garbage/empty. TDD — failing test first.
- **Capture hook + sweep** — tested against fixture transcript directories; assert files land
  in the store with the directory structure preserved and that re-running is idempotent.
- **ccusage** is mocked at the process boundary; analysis tests feed a canned ccusage `--json`
  payload and assert the CSV/JSON join and rollup are correct.
- **setup** — tested against a fixture `settings.json` to confirm existing hooks are preserved.
